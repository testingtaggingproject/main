Tag Diagnostics - 20%
Here are the steps to get started with tag diagnostics and empathize with what our users go through. Use in-product text, Ask Advisor (our AI chat tool), help center, videos, blogs, and other resources to figure these things out and document what you learn as you go. Ideally, you only use what's available to our users to see what information they might be missing in their tagging journey.

This is meant to pair with what JR created in TaskFlow.
Part 1: Understand tagging
Step 1: Launch the website
Go to https://codesandbox.io/ 
Click "Try for free," then "HTML + CSS," and then "Fork template."
Copy the code from here and then paste it into the left side of the site.
On your keyboard, press command+S to save the changes.
You should see your changes on the right side of the screen in preview.
Open the preview in a new tab to see the site.
Step 2: What to test
Initial setup
Create the following accounts
Google Analytics
Google Ads dollar-a-day
Google Marketing Platform
Shopify, Wordpress, Wix, or another content management system (CMS)

See tag diagnostics
Now that you have an account, go to your Tag Diagnostics and Data diagnostics.

Start sending data
Send data to any of the products and see the data come through via both
the Google tag (GTE)
Google Tag Manager (GTM) through a container

Configurations
Add domains to a Google Analytics configuration
Add a config command to your code
Set up conversion linker through Floodlight
Implement a transaction ID for a purchase event

If there's time
Set up consent mode
Part 2: Audit existing tag diagnostics messages
Now that you understand tagging, review each tag diagnostic and look for
Patterns we can create so content is consistent across the board
Information that's missing or too complex for users
Where we can have the biggest impact on the user experience

Check with Rudhra that this list is comprehensive. We've created a bunch of new diagnostics and had a lot more user interaction since this list was created.
Part 3: Take a look at the tag diagnostics data
I've included the qualitative data here and the quantitative data is in the Engineering's data dashboard. Start to work with Eng and PM to get more information about who we're designing for. Look at our personas and identify who we're designing for. Start to map out their journey to the diagnostics. Investigate whether research is needed to help validate your hypotheses or if there are any user tests you can do independently.
Part 4: Create your final presentation
Collate all the information you've collected (your POV, guidelines, data, etc.) to tell a compelling story about the content and how it improves the user experience.
